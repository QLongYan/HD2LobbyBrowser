# 发布指南（给自己看）

> 目标：让程序里的「升级」按钮能自动下载到新版本。
> 只需要记住一句话：**代码放仓库，exe 放 Release 附件。**

---

## 〇、先搞清楚两件事

| 东西 | 放哪 | 为什么 |
|---|---|---|
| README、源码、json 数据、build.bat | 仓库文件区（Code 页） | 体积小，方便别人看和编译 |
| **HD2LobbyBrowser.exe**（13 MB） | **Releases 附件** | 仓库不适合放大文件（每次更新都会让仓库永久变大）；Release 附件专门放安装包，单个可到 2 GB |

程序的升级地址是固定的：

```
https://github.com/QLongYan/HD2LobbyBrowser/releases/latest/download/HD2LobbyBrowser.exe
```

所以只要**每次 Release 的附件都叫 `HD2LobbyBrowser.exe`**，这个地址永远有效，程序不用改代码。

---

## 一、第一次：把文件传到仓库

1. 打开 https://github.com/QLongYan/HD2LobbyBrowser
2. 点页面中间的 **uploading an existing file**（或右上角 `Add file` → `Upload files`）
3. 把 `github发布` 文件夹里的这些东西**全选拖进去**：
   - `README.md`
   - `LICENSE`
   - `CHANGELOG.md`
   - `.gitignore`
   - `build.bat`
   - `发布指南.md`
   - `release-notes-v21.md`
   - `源码` 文件夹（整个拖）
4. 下面 Commit changes 的输入框写：`V21 首次上传`
5. 点绿色 **Commit changes**

> 拖文件夹：Chrome / Edge 支持直接把文件夹拖进网页，会保留目录结构。
> `.gitignore` 是隐藏文件（以点开头），Windows 资源管理器里如果看不到，在「查看」里勾上「隐藏的项目」。

---

## 二、第一次：建 Release 并上传 exe

1. 仓库首页，右侧栏点 **Releases** → **Create a new release**
   （或直接打开 https://github.com/QLongYan/HD2LobbyBrowser/releases/new）
2. **Choose a tag** 输入：`v21` → 点出现的 **Create new tag: v21 on publish**
   ⚠ 必须是 `v` + 数字，程序靠这个判断版本号；不要写 `V21-final`、`v21.0.1` 这类
3. **Release title** 写：`V21`
4. **Describe this release** 里，把 `release-notes-v21.md` 的内容整段复制进去
5. **Attach binaries**：把 `HD2LobbyBrowser.exe` 拖进那个虚线框，等它上传完
   ⚠ 文件名保持 `HD2LobbyBrowser.exe`，不要改成 `HD2LobbyBrowser (1).exe`
6. 确认 **Set as the latest release** 是勾上的
7. 点 **Publish release**

---

## 三、验证是否成功

浏览器打开这个地址，应该**直接开始下载 exe**：

```
https://github.com/QLongYan/HD2LobbyBrowser/releases/latest/download/HD2LobbyBrowser.exe
```

再打开软件：

- 如果版本号旁显示「已是最新版」→ 说明检查通了（V21 = 最新 v21）
- 想看「有新版」的效果：把 Release 的 tag 改成 `v22` 再发布，重开软件就会显示金色「有新版 V22」、「升级」按钮点亮

---

## 四、以后发新版（V22、V23…）

1. 改 `源码\hd2_lobby_browser.py` 里的 `VERSION = 22`
2. 双击 `build.bat`，等它生成 `dist\HD2LobbyBrowser.exe`
3. 更新 `CHANGELOG.md`，把本次改动写到最上面
4. 仓库 `Add file` → `Upload files`，把改过的源码 / CHANGELOG 传上去
5. 去 Releases → **Draft a new release**：
   - tag 写 `v22`（新 tag）
   - 标题写 `V22`
   - 说明从 CHANGELOG 里复制这一段
   - 附件拖入新的 `HD2LobbyBrowser.exe`
6. Publish

老版本用户下次开软件就会看到「有新版 V22」，点升级自动替换并重启。

## 五、常见问题

**Q：为什么不能直接把 exe 传到仓库文件区？**
A：网页上传单个文件限制 25 MB（命令行 100 MB），我们的 exe 13 MB 虽然能传，但每次更新都会在仓库历史里留一份 13 MB 的副本，几十个版本后仓库会变成几百 MB，clone 会非常慢。Release 附件不占仓库体积，且下载地址稳定。

**Q：Release 发错了想改？**
A：进 Releases → 点版本右上角铅笔图标编辑 → 可替换附件、改 tag、改说明。删掉某个附件后，`releases/latest/download/HD2LobbyBrowser.exe` 会 404，所以别删正在用的那个。

**Q：tag 写错了会怎样？**
A：程序只认开头的数字（`v21` / `21` / `V21.1` 都行，取第一个数字）。写成 `release-21` 会解析失败，用户那边会显示「已是最新版」或「检查更新失败」，不会误升级。

**Q：国内用户下载不了 GitHub 怎么办？**
A：程序内置了两个镜像兜底（`ghproxy.net`、`gh-proxy.com`），直连失败会自动尝试。仍然失败会弹提示，让用户去 B站 / A网下载。

**Q：GitHub API 有次数限制吗？**
A：未登录 60 次/小时/IP，只用于启动时查一次版本，正常使用不会触发。下载 exe 走的是网页地址，不消耗 API 配额。

**Q：可以不用 GitHub 吗？**
A：可以。在 exe 同目录放 `update_url.txt`，里面写一个 JSON 地址：

```json
{"latest": 22, "url": "公告页", "file": "https://你的直链/HD2LobbyBrowser.exe"}
```

程序会优先用这个源，读不到再回退 GitHub。
